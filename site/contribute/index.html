Contribute

Put a model on the scale

Two routes, one response format. For version 0.1 the pipeline is run by the maintainers: send a pull request or an email with the files described here, and the model is placed with item difficulties anchored, then published with its ability and standard error.

Version 0.1 has no automated submission service. Open a pull request against the repository or write to the maintainers; turnaround is a few days for the representation panels and depends on screen size for perturbation.

Route 1: embeddings

For the representation component you ship embeddings and we run the frozen probe. For each panel you want to be scored on, provide one matrix per panel of shape (cells × dimensions) for every cell in the panel, training and test, in the panel's cell order, as .npy or an .h5ad with the embedding in obsm. Panels are distributed as .h5ad files with raw counts, the split column and the stratum labels; the test labels are included, because the probe is ours and the split is by whole donors, studies or tissues. State which cells your model saw during pretraining.

This is the same route the scVI respondents took: scripts/extract_scvi_embedding.py writes the matrix, scripts/append_repr_responses.py runs the probe and appends the responses, and a refit places the model.

Route 2: predictions

For the perturbation component you ship predicted pseudobulk deltas. For each screen and split, provide one matrix of shape (test items × genes) in the screen's gene order, one row per held-out condition of each fold, using the published fold assignment in the items table (fold_group). Your model may train on the training folds' cells and conditions and on all control cells; it must not see the held-out conditions. Scoring applies the fixed metric and pass rule. The scGen and scVI counterfactual respondents took this route through scripts/append_pert_scores.py.

Route 3: a response table

If you reproduce the probe or the pass rule yourself, the minimal submission is the response table both components share, one row per item and model:

item_id            respondent_id     k   n
repr_pool_v0::cell_0001   my_model_v1   1   1
tahoe100m::drugX::ctx=A549::dose=0.05   my_model_v1   0   1

k is the number of passes out of n trials, so cell-level items have n = 1 and stratum-level items the stratum size. Item identifiers must match the published items tables exactly. Response tables are checked against the items we hold out: a table that passes items the published pool shows as unreachable triggers a manual look before placement.

Anchored placement

A new model is first placed with every item difficulty fixed at its current value, which takes seconds and leaves every published ability unchanged. Its ability, standard error, pass rate and outfit go on the board with the scale version it was placed on. At the next recalibration every model is refit together.

The contamination register

For every learned model, declare for each source whether it was in the pretraining corpus, in any fine-tuning data, or clean. Sources are listed on the datasets page; CELLxGENE atlases and scBaseCount overlap heavily with the pretraining data of current single-cell foundation models, so most entries will not be clean, and that is fine. The register is published alongside the ability and is what makes it interpretable.

House rules

  • Respondent names are stable strings reused across every run and version; a model is never renamed in one run only.
  • Published items are never modified. A fix to a panel or screen produces a new panel or screen and a new scale version.
  • Classical respondents and floors are always refit alongside submissions, so the bottom of the scale is checked every time.
  • Abilities from different scale versions are never compared without saying so.
  • Submissions that only tie the baseline on most items are kept as diagnostics and flagged as misfit, not ranked.

Where a new source helps most

  • Representation items above +2 logits that are not label noise: state-level annotations such as treatment or disease state, at pseudobulk resolution.
  • Perturbation screens with chemical descriptors, so that unseen-compound prediction becomes a learnable split.
  • A cytokine to gene mapping for the Parse screen, so that unseen-cytokine items can use the control-coexpression gene embedding.
  • Foundation-model embeddings and perturbation predictions with a complete contamination declaration.
